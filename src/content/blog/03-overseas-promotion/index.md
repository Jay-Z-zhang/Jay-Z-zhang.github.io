## 为什么要做海外社媒？

如果你的产品面向全球市场，**海外社媒就是你的免费获客渠道**。

但和国内抖音、小红书不同，海外平台的玩法、用户习惯、内容风格完全不同。选错平台 = 浪费时间。

---

## 第一梯队：基础设施

### 1. Gmail / Google 账号

**为什么重要？**

几乎所有海外平台都需要 Google 账号注册。它是你的「数字身份证」。

**行动清单：**
- [ ] 注册专用 Google 账号（不要和个人邮箱混用）
- [ ] 开启两步验证
- [ ] 设置专业的头像和名字

---

### 2. Reddit

**定位：全球最大的论坛集合**

| 特点 | 说明 |
|------|------|
| **用户画像** | 技术爱好者、早期采用者、深度讨论者 |
| **内容风格** | 长文、深度分析、真实经验分享 |
| **流量潜力** | 极高（热门帖子可带来数万 UV） |
| **SEO 价值** | 极高（Google 优先索引 Reddit 内容） |

**运营要点：**

❌ **不要做的事：**
- 直接发广告
- 批量发帖
- 用营销号语气

✅ **正确做法：**
- 找到你的 niche subreddit（如 r/SaaS、r/startups）
- 先贡献价值（回答问题、分享经验）
- 1-2 个月后，自然引入你的产品
- 用「我在做一个 XXX，想听听大家意见」的方式引入

**案例：**
> 一个独立开发者在 r/webdev 分享「我如何用 Next.js 做了一个 XXX」，帖子获得 500+ upvotes，产品当天注册量从 10 人暴涨到 300 人。

---

### 3. Twitter / X

**定位：实时信息 + 算法推荐**

| 特点 | 说明 |
|------|------|
| **用户画像** | 创业者、投资人、开发者、KOL |
| **内容风格** | 短平快、观点鲜明、互动性强 |
| **流量潜力** | 中等（依赖算法和互动） |
| **SEO 价值** | 中等（内容实时性强，长尾效应弱） |

**运营要点：**

**内容公式：**
```
观点 + 数据/案例 + 互动问题
```

**示例：**
> 「大多数 SaaS 创始人犯的错误：花 80% 时间做产品，20% 时间做营销。
> 
> 我的经验正好相反：30% 产品，70% 营销。
> 
> 结果是：MRR 从 $0 到 $5K 只用了 4 个月。
> 
> 你们觉得这个比例合理吗？」

**增长技巧：**
- 每天发 3-5 条推文
- 回复大 V 的推文（蹭流量）
- 用 Thread 形式发长内容
- 参与 #buildinpublic 话题

---

### 4. Facebook

**定位：品牌长期建设 + 社群运营**

| 特点 | 说明 |
|------|------|
| **用户画像** | 大众用户、中小企业主 |
| **内容风格** | 图文、视频、直播 |
| **流量潜力** | 高（但 organic reach 持续下降） |
| **SEO 价值** | 低（Facebook 内容不被 Google 索引） |

**运营要点：**

**Facebook Group > Facebook Page**

- Page 的 organic reach 已经 < 5%
- Group 的 engagement 是 Page 的 10 倍

**行动清单：**
- [ ] 创建一个和你的产品相关的 Group
- [ ] 邀请早期用户加入
- [ ] 每天分享有价值的内容（不是广告）
- [ ] 鼓励用户提问和讨论

## 第二梯队：精准流量池

### 5. Indie Hackers

**定位：独立开发者社区**

| 特点 | 说明 |
|------|------|
| **用户画像** | 独立开发者、SaaS 创始人 |
| **内容风格** | 收入公开、经验分享、产品发布 |
| **流量潜力** | 中等（精准但量不大） |
| **转化价值** | 极高（用户本身就是目标客户） |

**运营要点：**

**核心策略：先建立信任，再推广产品**

1. 前 1 个月：只回答问题、分享经验
2. 第 2 个月：开始分享你的「build in public」历程
3. 第 3 个月：自然引入产品链接

**禁忌：**
- 不要一注册就发产品链接
- 不要只发自己的内容
- 不要夸大收入数据

---

### 6. ProductHunt

**定位：新产品发布平台**

| 特点 | 说明 |
|------|------|
| **用户画像** | 早期采用者、产品经理、投资人 |
| **内容风格** | 产品发布、功能展示、用户评价 |
| **流量潜力** | 高（热门产品可带来数千 UV） |
| **转化价值** | 高（用户有尝试新产品的意愿） |

**发布策略：**

**发布前 1 周：**
- [ ] 完善产品页面（截图、视频、描述）
- [ ] 准备 launch 邮件列表
- [ ] 联系 5-10 个 Hunter（有影响力的人帮你发布）

**发布当天：**
- [ ] 美东时间 00:01 发布（抢占当日榜首）
- [ ] 回复每一条评论
- [ ] 在 Twitter/Reddit 同步宣传
- [ ] 鼓励用户投票和评论

**发布后：**
- [ ] 感谢所有投票和评论的人
- [ ] 分析流量和转化数据
- [ ] 收集用户反馈，快速迭代

---

### 7. Hacker News

**定位：技术极客聚集地**

| 特点 | 说明 |
|------|------|
| **用户画像** | 开发者、技术创业者、投资人 |
| **内容风格** | 技术深度文章、产品发布、行业分析 |
| **流量潜力** | 极高（首页可带来数万 UV） |
| **转化价值** | 中等（用户偏技术，不一定买） |

**运营要点：**

**什么样的内容能上首页？**

✅ **受欢迎的内容：**
- 技术深度文章（如「我是如何用 Rust 重写 XXX 的」）
- 有趣的产品（如「我做了一个能用 AI 写代码的工具」）
- 行业分析（如「2025 年 SaaS 定价趋势」）

❌ **不受欢迎的内容：**
- 营销软文
- 夸大其词
- 没有技术深度的内容

**提交技巧：**
- 标题要简洁、有信息量
- 描述要客观，不要自夸
- 选择合适的时间提交（美东时间上午 9-11 点）

## 核心运营逻辑

### 1. 快速迭代

> 先做一个能用的版本，用真实用户反馈来优化，而不是在办公室里「闭门造车」。

### 2. 协作分工

> 技术 + 营销的组合最高效。一个人写代码，一个人做内容，速度翻倍。

### 3. 最大化 SEO

> 找到带来流量的关键词，围绕它做多个 landing page，吃透长尾流量。

### 4. 付费加速

> 一旦验证了盈利模型，尽早投广告，抢占关键渠道，建立竞争壁垒。

### 5. 保持灵活

> 如果主渠道遇到政策变化或流量下降，要有备用方案随时切换。
